# reason_583019 - Upgrade Windows use vicinity random, not only orthogonal neighbors

## Why THE-LARGER-SYSTEM changed

The first Return Walk pass converted only orthogonally adjacent solids in a 5s two-Upgrade
window. That made Return Gold feel like a tiny local swap instead of a walk across a Public
Room. Recording the vicinity rule keeps later work from shrinking the pool back to four
neighbors or letting Resident POST coordinates.

## How it serves the larger system

- Keeps world authority on the play socket: pose at fire time still chooses tiles, now from a
  Chebyshev square around Resident so Return Gold can jump to existing solids that are not
  next to the claim.
- Uniform random among eligible y === 0 ordinary solids (no new floor cubes) preserves the
  "convert, do not spawn" rule while making the walk read as a larger space.
- Eight Upgrades over 20s gives the room time to change without adding a Resident Upgrade HTTP
  seam or mixing prepaid Return Budget into the Stream Faucet.
