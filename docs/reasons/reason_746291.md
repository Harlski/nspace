# reason_746291 — Player-visible product strings go through Message Catalogs

**Why:** Localization infra (`@nspace/i18n`, Supported Locales `en` / `tr` / `pt-BR`, Player Menu Language) is landing. Without a durable principle, new features would keep hard-coding English and reintroduce string drift between surfaces.

**How it serves the larger system:** One shared Message Catalog keeps client (and later server) chrome coherent across locales, while English remains the required source of truth and alternate locales may lag via fallback. Explicit exemptions (`/admin/*`, user-authored text, third-party chrome, legal bodies) keep the rule practical and avoid over-scoping operator tooling or player content.

**Change:** Added a Principles bullet in `docs/THE-LARGER-SYSTEM.md`; companion checklist note in `docs/process.md`; status rewrite in `docs/localization.md`.
